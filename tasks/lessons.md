# 经验沉淀 (Lessons Learned)

## UI & CSS
- [触发条件] 移动端按钮点击出现黑色半透明矩形 -> [根因] 浏览器默认的 `-webkit-tap-highlight-color` 行为 -> [正确方案] 设置 `WebkitTapHighlightColor: 'transparent'`。
- [触发条件] 按钮点击出现蓝色/黑色边框 -> [根因] 默认的 `focus` outline -> [正确方案] 使用 `outline-none` 或 `focus:outline-none`。
- [触发条件] 随着窗口缩放，时间轴卡片等具有绝对定位的元素插入或超出了左侧边栏区域 -> [根因] `App.tsx` 中的缩放父容器（或时间轴 Canvas 容器）使用了 `overflow-auto`，未裁剪越界的子元素 -> [正确方案] 在对应的父级缩放视图容器上施加严格的 `overflow-hidden`。

## SVG 渲染机制
- [触发条件] 球面 UI 边上的长弧形文字标签被截断（例如变成“视频动作捕 ”、“UEPython开”） -> [根因] SVG `<textPath>` 在没有正确定义原点偏移对齐方式时，如果 `<textPath>` 的长宽超过了所分配的几何曲线长，字就会被 SVG 引擎强制截掉。代码错误地将 `textAnchor="middle"` 写在了 `<textPath>` 节点内，而它必须作用于其父 `<text>` 节点上。加上 `startOffset="50%"` 后文字从拱形中点向右排，一半直接溢出跑出外延被切 -> [正确方案] `textAnchor="middle"` 必须直接作为 SVG `<text>` 的属性，配合 `startOffset="50%"` 才能确保长文字以弧线中点为中心向两侧对称渲染。同时适度加大 `arcAngle` 保障线段自身物理长度。

## 响应式布局
- [触发条件] 时间轴内容超出屏幕导致滚动 -> [根因] 固定间距在高密度内容下失效 -> [正确方案] 减小 `nodeSpacing` 并动态计算缩放比例 `scale` 适配容器宽高。
- [触发条件] 移动端与桌面端信息不一致 -> [根因] 响应式组件中遗漏字段渲染 -> [正确方案] 在所有断点视图中统一数据渲染逻辑。
- [触发条件] 桌面窗口调整时间轴时字号太小或者绝对底图错位 -> [根因] 粗暴移除 `scale()` 会破坏绝对定位 -> [正确方案] 建立基础虚拟画布（如900x500/400x动态高度），使用 `Math.min(容器宽/画布宽,  容器高/画布高)` 来进行完整 `scale` 缩放以兼顾响应与完美比例。
- [触发条件] 容器虽然设置了 `justify-center`，但是高度较小的时间轴被强制居中，导致上方或下方面向背景底图留出大片绝对红区空白 -> [根因] 居中轴排版和强设定 padding、margin 加成了留白空隙 -> [正确方案] 移动端流式场景通常不该绝对居中，应当换用 `justify-start`，从头渲染并将内容虚拟高度(`mobileVirtualHeight`)按可见物理容器等比占满即可。
- [触发条件] 在移动/竖屏布局模式切换的中间临界态（480-768px）下，通过 `scale` 强行缩放出来的组件比例畸形或巨大化 -> [根因] `isMobile` 为 true 时，仍然允许高容忍度的 `Math.min(widthScale, heightScale, 1.5)` 甚至更高上限，导致极长屏幕下小屏元素被放大 150%。 -> [正确方案] `isMobile` 分支应当将其最大 `scale` 限制死至 `1.0`（如果它是为类似 iPhone 屏幕标定的），不容许过度超大。
- [触发条件] 响应式容器内包含文字、描边、以及带有绝对偏移的浮动动画时图形偏小 -> [根因] `sizeScale` 计算未考虑固有常数 -> [正确方案] 在从最大容器反推数学半径时，减去常数然后再除以基准半径的做法会“双重扣除”文字和卫星的内置比重差。若 `REF_RADIUS` 直接涵括了整个 UI 构件的最外延，那最正确的 `sizeScale` 公式应当纯粹为 `max容器空余 / REF_RADIUS`。
- [触发条件] 清除未使用的代码时使用 ts-prune 等静态分析工具 -> [根因] ts-prune 可能会将通过 index.ts 重导出并在其他文件中引用的组件标记为未使用 -> [正确方案] 清理代码前，务必使用全局搜索确认组件的实际使用情况，避免误删。
- [触发条件] TypeScript 报 "Object literal may only specify known properties" 错 -> [根因] 清理代码后，对应的 Context 默认设置仍保留了被删除功能相关的属性配置，但类型已被移除 -> [正确方案] 移除功能时应同步清理 Context 默认配置项。
